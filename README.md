# Shot Roulette

Полноэкранная пиксельная игра: камень, ножницы, бумага и случайные шоты. Next.js, TypeScript, Canvas и Zustand. Игра работает в браузере без сервера и регистрации.

Запуск: `npm install`, затем `npm run dev`. Откройте http://localhost:3000.

Проверка: `npm test`, `npm run typecheck`, `npm run build`.

Сборка создаёт статическую папку `out`. Для Firebase Hosting уже подготовлен `firebase.json`. Выполните `npx firebase-tools login`, `npx firebase-tools use --add`, затем `npx firebase-tools deploy --only hosting` для своего Firebase-проекта.

Логика находится в `src/game`: GameEngine управляет конечным автоматом, RockPaperScissors определяет победителя, ShotManager перемешивает шоты, SobrietySystem управляет трезвостью, GameSettings проверяет параметры, GameStore связывает действия с Zustand. Компоненты GameCanvas и GameUI отвечают за визуал и интерфейс.

ИИ получает только ID доступных шотов. Конец игры проверяется до восстановления. Настройки сохраняются в localStorage. Звук синтезируется браузером после первого действия.

Настройки: 1–12 очков трезвости и шотов, 1–количество шотов алкоголя, 0–12 восстановления, скорость 0.5× / 1× / 2×. Если восстановление равно количеству алкоголя или больше него, партия может идти бесконечно. Для короткой партии уменьшите восстановление.

## Визуал

Игра занимает весь viewport без журнала, карточек и прокрутки. Отдельное стартовое меню открывается поверх бара; настройки доступны кнопкой «Настройки». Кнопка ⛶ дополнительно включает системный полноэкранный режим браузера.

Все изображения — настоящие PNG-ассеты в `public/art`: фон со столом, лампой и силуэтом; руки игрока и оппонента; закрытый/пустой/раскрытые шоты; кнопки; индикаторы трезвости. Canvas загружает изображения и рисует их через drawImage с выключенным сглаживанием. CSS отвечает только за расположение DOM, текст и прозрачные области нажатия.

Исходные атласы: `hands-atlas.png`, `props-atlas.png`. Нарезка: `node scripts/slice-atlases.cjs` (использует sharp из зависимостей Next.js). Карта ассетов и размещение: `src/art/assets.ts`. Подробнее о происхождении и промптах — в `public/art/README.md` и `public/art/prompts.md`.

Phaser не требуется для одной статичной сцены с пошаговой логикой. Текущий рендерер можно заменить отдельно от GameEngine, если понадобятся дополнительные игровые сцены и сложные анимации.

## Анимации

Персонаж отделён от фона и дышит/покачивается даже в ожидании. Выпивание использует 8 цельных PNG-кадров каждого участника: рукав, кисть, пальцы и удерживаемый стакан нарисованы вместе. Оппонент включает голову, плечо и корпус. Части руки не растягиваются между точками. Жесты используют отдельный атлас цельных поз. `src/art/renderScene.ts` отвечает за слои и отрисовку, `src/art/animation.ts` задаёт общий таймлайн для рендерера и переходов состояния.

Выпивание длится 3.6 секунды при скорости 1×: дотянуться → обхватить → поднять → наклонить и опустошить → поставить пустой стакан → убрать руку. Вода раскрывается с голубыми частицами, алкоголь — с янтарными, потерей очка и реакцией персонажа/камеры. Финальный экран появляется только после раскрытия последнего шота; проверка победы в логике по-прежнему происходит до восстановления.

Проверка анимаций в Edge: `node scripts/animation-qa.cjs <путь к модулю playwright>`. Сценарии фиксируют случайность, проверяют действия обоих участников, воду, алкоголь, блокировку выбора во время движения и порядок раскрытия последнего шота. Кадры проверки сохраняются в `artifacts/animation`.
